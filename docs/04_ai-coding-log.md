# AI 코딩 도구 사용 기록

| 항목 | 내용 |
|---|---|
| 사용 도구 | Claude (claude.ai, 모델 Claude Opus 5.5) · 파일 작성·터미널 실행이 가능한 작업 환경 |
| 사용 일시 | 2026-09-29 (KST) 한 번의 대화 세션 |
| 사용 방식 | 김성태가 미션 문서와 목표를 주고, Claude 가 조사·설계·코드·테스트·문서 초안을 만들며, 김성태가 검토·배포·최종 확인 |
| 증빙 | ① 이 문서 ② 대화 화면 캡처 (아래 5장에 추가) |

> AI 가 코드를 대신 썼더라도, 어떤 판단을 왜 했는지와 어디서 틀렸는지를 설명할 수 있어야 한다는 미션 목표에 맞춰 **결정 근거와 오류 수정 과정**을 중심으로 기록했습니다.

## 1. 요청 (김성태 → Claude)

> "Codyssey A1-3 인데 권한 다 줄께 끝까지 만들어줘" + 미션 문서 전문 첨부

요구사항을 체크리스트로 바꿔 진행했습니다: 3개 이상 섹션과 메뉴, 반응형, AI 기능(입력 → 결과), 실패 처리, `api/` Python 서버리스 함수, `requirements.txt`, 환경 변수 키 관리, README, 기획서, 스크린샷, AI 사용 증빙, GitHub 커밋 이력, Vercel 배포.

## 2. 진행 순서와 AI 활용 방식

| 단계 | Claude 가 한 일 | 사람이 확인할 점 / 결과 |
|---|---|---|
| 1. 이전 미션 확인 | A1-2(여행 추천 CLI) 대화를 찾아 환경 변수 이름(`GEMINI_API_KEY`, `OPENAI_API_KEY`) 규칙을 이어서 사용 | 미션 간 일관성 |
| 2. 공식 문서 확인 | Vercel Python 런타임(2026-08-12 개정), 함수 최대 실행 시간, Gemini 모델·요금·한도, Claude 모델 목록을 직접 조회 | 기억에 의존하지 않고 최신 문서로 결정 (4장) |
| 3. 기획 | 후보(논문 요약 도우미, 공시 텍스트 분석 등)와 비교해 "제조기업 AX 준비도 진단" 제안, 기획서 작성 (공시 분석은 기존 DART-Foresight AI 저장소와 겹쳐 제외) | **아이디어는 Claude 제안** → 김성태 검토 결과를 5장에 기록 |
| 4. 백엔드 | `api/diagnose.py`, `api/health.py` 작성, 단위 테스트 45개 작성·실행 | 테스트가 D1(로그 키 노출 가능성) 발견 → 수정 |
| 5. 프론트엔드 | HTML 5개 섹션, CSS 반응형·다크 모드, JS 폼 검증·fetch·결과·실패 처리, SVG 레이더 차트 | |
| 6. 로컬 서버 | Vercel 로그인 없이 전체를 돌리는 `scripts/dev_server.py` (목업·오류 재현 모드) | 키 없이 실패 화면까지 재현 가능 |
| 7. 브라우저 점검 | 헤드리스 크롬으로 3개 화면 크기, 실패 10여 종 자동 점검 | D2(hidden 무시), D3(첫 클릭 무시) 발견 → 수정 |
| 8. 화면 검토 | 스크린샷을 직접 보고 결과 화면 배치(좌우 높이 차이), 점수 막대 정렬, 모바일 차트 글자 크기 수정, 입력 요령 패널 추가 | 사람 눈으로 보는 단계가 따로 필요했음 |
| 9. 문서화 | README, 테스트 리포트, 트러블슈팅, 학습 노트, 배포 가이드 | 배포 URL 은 README, 배포 점검 결과는 테스트 리포트 7장에 기록 |
| 10. 독립 검토 | 만든 과정을 모르는 별도 AI 에이전트에게 과제 문서와 저장소만 주고 감사 → 6건(R1~R6) 수정, 단위 테스트 59개로 확대 | 스스로 채점하지 않기 위한 단계 (`docs/03_troubleshooting.md` A-2) |
| 11. 배포 | GitHub 업로드, Vercel 설정 화면 안내, 배포 뒤 `/api/health`·첫 화면·405 응답·자동 재배포 확인 | 김성태가 Vercel Import 와 키 입력, 자동 선택된 Python 프리셋을 Other 로 변경 (`docs/03_troubleshooting.md` B-2). 김성태가 배포 사이트에서 실제 AI 결과(15.4초)와 모바일 화면 확인 |

커밋 이력은 이 순서를 그대로 따릅니다: `git log --oneline` 으로 확인할 수 있습니다.

## 3. AI 가 만든 코드에서 발견한 오류와 수정

| 번호 | 오류 | 원인 (말로 설명) | 수정 방향 |
|---|---|---|---|
| D1 | 예상 못한 오류가 나면 로그에 키가 찍힐 수 있음 | traceback 이 예외 메시지를 그대로 출력 | 출력 전에 키 문자열을 `***` 로 가림 |
| D2 | 로딩·오류·결과 카드가 처음부터 보임 | CSS `display: flex` 가 HTML `hidden` 보다 우선 | `[hidden] { display: none !important; }` |
| D3 | 오류를 고친 뒤 첫 클릭이 무시됨 | 포커스가 빠질 때 오류 문구가 사라져 버튼이 이동, 클릭이 버튼 밖에서 끝남 | 타이핑 중(input 이벤트)에 오류 문구 제거 |
| R1 | 따옴표 5개로 프롬프트 구분 기호를 되살릴 수 있음 | 문자열 치환이 한 번만 훑음 | 정규식으로 3개 이상 모두 치환 |
| R2 | health 가 정상이어도 진단은 설정 오류 | health 가 모델·제공자 설정을 검사하지 않음 | 진단 함수와 같은 규칙으로 `config_ok` 계산 |
| R3·R4 | 서버 호출 제한 없음, CLI 배포 시 `.env` 업로드 위험 | 브라우저 제한만 있음, `.vercelignore` 누락 | IP 1분 6회 제한, `.vercelignore` 에 `.env` 추가 |

자세한 재현·확인 과정: [03_troubleshooting.md](03_troubleshooting.md)

## 4. 설계 결정과 근거 (평가 때 설명할 내용)

| 결정 | 근거 |
|---|---|
| 단계(1~5)는 코드가 계산, 문장만 AI 생성 | 같은 점수면 항상 같은 단계가 나와야 신뢰할 수 있음 (정량과 정성 분리) |
| Gemini 기본 + Claude·OpenAI 선택 | 무료 등급이 있는 Gemini 로 누구나 재현, 키만 바꾸면 제공자 교체 (특정 회사에 묶이지 않음) |
| 기본 모델 `gemini-3.5-flash-lite` | 2026년 9월 공식 문서: 2.5 계열은 기존 사용자 위주로 제한, 새 프로젝트는 3.5 Flash-Lite 또는 3.8 Flash 권장. 빠르고 무료 등급 제공 |
| Gemini 는 `generateContent` REST 사용 | 문서상 새 Interactions API 를 권장하지만 `generateContent` 도 "fully supported" 로 명시. 응답 형식이 널리 알려져 있고 응답 스키마로 JSON 을 강제할 수 있어 선택 |
| SDK 대신 `requests` 로 직접 호출 | 제공자 3곳을 같은 방식으로 다루고, 시간 제한(연결 5초, 응답 40초)을 직접 설정하기 쉬움 |
| `api/` 파일 방식 + `BaseHTTPRequestHandler` | 미션 조건(api 폴더 Python 함수)과 Vercel 공식 문서의 지원 방식. FastAPI 등을 넣으면 앱 방식이 우선돼 `api/` 파일이 함수가 되지 않음 |
| 함수 최대 실행 60초, AI 대기 40초, 브라우저 50초 | 서버가 먼저 정리된 오류(504 JSON)를 보내고, 그래도 안 오면 브라우저가 멈추도록 순서를 맞춤 |
| 결과는 `textContent` 로만 표시 | AI 응답에 HTML 이 섞여도 실행되지 않게 (XSS 방지, 자동 점검으로 확인) |
| 요청 중 버튼 잠금 + 응답 뒤 3초 제한 + 서버 IP 1분 6회 | AI API 는 호출마다 비용·쿼터를 쓰므로 연타 방지. 브라우저 제한은 우회될 수 있어 서버에서도 제한 |
