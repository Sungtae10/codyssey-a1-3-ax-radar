# 학습 노트: 미션 목표 6가지를 내 말로 설명하기

평가 때 "AI 가 해 줬어요"가 아니라 **내가 이해한 말**로 설명하기 위한 노트입니다. 각 항목은 ① 한 줄 요약 ② 쉬운 비유 ③ 우리 코드의 위치 ④ 예상 질문 순서입니다.

```text
[브라우저]                         [Vercel]                              [AI 회사]
index.html / css / js  --fetch-->  api/diagnose.py (Python 함수)  --->  Gemini API
   ① 입력 검사                       ② 입력 재검사, 단계 계산                ③ 문장 생성
   ⑥ 화면에 그리기   <--JSON------   ⑤ JSON 정리                   <---  ④ JSON 텍스트
                                     (API 키는 여기 환경 변수에만)
```

---

## 1. HTML, CSS, JavaScript 의 역할

- **한 줄 요약**: HTML 은 무엇이 있는지(구조), CSS 는 어떻게 보이는지(모양), JavaScript 는 무엇을 하는지(동작)를 정한다.
- **비유**: 집으로 치면 HTML 은 벽과 방, CSS 는 벽지와 가구 배치, JavaScript 는 전기 스위치와 초인종이다.
- **우리 코드**
  - `index.html`: 5개 `<section>` (홈, 진단 모델, AI 진단, FAQ, 소개), 입력 폼, 결과를 담을 빈 자리
  - `css/style.css`: 색 변수(`--primary` 등)와 다크 모드, `@media (max-width: 860px)` 에서 햄버거 메뉴, 640px 이하 한 줄 배치
  - `js/main.js`: 메뉴 열기·닫기, 현재 섹션 강조, 다크 모드 / `js/diagnose.js`: 폼 검사, 서버 호출, 결과 그리기 / `js/radar.js`: 레이더 차트
- **예상 질문**: "반응형은 어떻게 했나요?" → CSS 미디어 쿼리로 화면 폭이 860px 이하면 메뉴를 접고, 640px 이하면 카드와 버튼을 한 줄로 쌓았습니다. 390·768·1440px 에서 가로 스크롤이 없는지 자동 점검했습니다.

## 2. 입력이 fetch 요청이 되고, 응답이 화면에 반영되는 흐름

- **한 줄 요약**: 버튼을 누르면 JS 가 입력을 모아 JSON 으로 서버에 보내고(fetch), 돌아온 JSON 을 읽어 빈 자리에 글자를 채운다.
- **비유**: 식당 주문서. 손님(사용자)이 주문서를 쓰면 종업원(JS)이 빠진 칸을 확인하고 주방(서버)에 전달, 요리(결과)가 나오면 테이블(화면)에 차린다.
- **우리 코드 (`js/diagnose.js`)**
  1. `submitDiagnosis` 가 제출 이벤트를 받고 기본 동작(새로고침)을 막는다.
  2. `collectPayload` 가 입력값을 객체로 모은다.
  3. `validatePayload` 가 빈 칸을 찾는다. 있으면 `showFieldErrors` 로 안내하고 **서버를 부르지 않는다**.
  4. `fetch('/api/diagnose', { method: 'POST', body: JSON.stringify(payload) })` 로 요청한다.
  5. `readJson` 으로 응답을 읽는다. (JSON 이 아니면 null, 예: Vercel 기본 오류 화면)
  6. 성공이면 `renderResult` 가 `textContent` 로 결과를 채우고, 실패면 `describeFailure` 가 오류 코드별 안내를 만든다.
- **예상 질문**: "왜 innerHTML 이 아니라 textContent 인가요?" → AI 응답에 `<img onerror=...>` 같은 코드가 섞여도 글자로만 보이게 하려고요. 실제로 그런 응답을 넣어 실행되지 않는 것을 자동 점검했습니다.

## 3. Vercel Serverless Functions 와 프론트에서 백엔드를 부르는 구조

- **한 줄 요약**: 서버를 24시간 켜 두지 않고, 요청이 올 때만 Vercel 이 `api/` 폴더의 Python 파일을 실행해 주는 방식이다.
- **비유**: 콜택시. 평소엔 차가 대기하지 않다가 부르면(요청) 와서 태워 주고(실행) 간다. 그래서 관리할 서버가 없다.
- **우리 코드**
  - 파일 경로가 곧 주소: `api/diagnose.py` → `/api/diagnose`, `api/health.py` → `/api/health`
  - Vercel 은 파일 안의 `handler` 클래스(`BaseHTTPRequestHandler` 상속)를 찾아 `do_POST` 를 실행한다.
  - 프론트는 같은 사이트 주소(`/api/diagnose`)로 부르므로 다른 도메인 문제(CORS)가 없다.
  - `vercel.json` 에서 함수 최대 실행 시간을 60초로 정했다.
- **예상 질문**: "첫 요청이 느린 이유는?" → 잠들어 있던 함수를 깨우는 시간(콜드 스타트)이 더해지기 때문입니다. 그래서 지연 안내 문구를 넣었습니다.

## 4. 환경 변수로 API 키를 관리해야 하는 이유

- **한 줄 요약**: 키는 돈이 나가는 비밀번호라서, 누구나 열람 가능한 곳(브라우저 코드, GitHub)에 두면 안 되고 서버의 환경 변수에만 둔다.
- **비유**: 현관 비밀번호를 대문에 써 붙이지 않는 것. 브라우저로 내려가는 JS 는 개발자 도구에서 누구나 읽을 수 있고, 공개 저장소의 키는 자동 수집 프로그램이 몇 분 안에 찾아낸다.
- **우리 코드**
  - 로컬: `.env` 파일 (`.gitignore` 로 커밋 차단), 예시는 값이 빈 `.env.example`
  - 배포: Vercel > Settings > Environment Variables
  - `api/diagnose.py` 의 `pick_provider` 가 `os.environ` 에서만 키를 읽는다.
  - 키는 URL 이 아니라 헤더(`x-goog-api-key`)로 보내고, 로그에서는 `redact` 로 가린다. `/api/health` 는 키 값 대신 "설정됨(true/false)" 만 알려 준다.
- **예상 질문**: "키가 유출되면?" → ① 발급처에서 즉시 폐기 ② 새 키를 Vercel 에 넣고 재배포 ③ 커밋에 들어갔다면 `git filter-repo` 로 이력에서도 지우고 강제 push. 폐기가 가장 먼저입니다.

## 5. 로컬 환경과 배포 환경의 차이, 수정·재배포 흐름

| 구분 | 로컬 (내 PC) | 배포 (Vercel) |
|---|---|---|
| 실행 | `python scripts/dev_server.py` | GitHub push 하면 자동 빌드 |
| 주소 | `http://localhost:3000` | `https://프로젝트이름.vercel.app` |
| 키 | `.env` 파일 | Vercel 환경 변수 (**바꾸면 재배포해야 적용**) |
| Python | 내 PC 버전 | 3.12 (Vercel 기본) |
| 파일 이름 | Windows 는 대소문자 구분 없음 | Linux 라서 대소문자 구분 |
| 시간 제한 | 없음 | 함수 최대 60초 (`vercel.json`) |

- **수정·재배포 흐름**: 코드 수정 → 로컬에서 확인 (`dev_server.py`, 단위 테스트) → `git commit` → `git push` → Vercel 이 새 배포 생성 → 배포 URL 에서 다시 확인. 문제가 생기면 Vercel 의 이전 배포로 즉시 되돌릴 수 있다(Instant Rollback).
- **예상 질문**: "로컬에선 되는데 배포에서 키 오류가 나요" → `.env` 는 GitHub 에 올라가지 않으니 Vercel 환경 변수에 따로 넣고 Redeploy 해야 합니다. `/api/health` 의 `key_configured` 로 확인합니다.

## 6. AI 가 만든 코드의 오류 원인을 찾고 수정 방향을 말로 설명하기

실제로 겪은 3가지로 설명합니다. (자세한 내용: [03_troubleshooting.md](03_troubleshooting.md))

1. **로그에 키가 남을 수 있었던 문제**: 오류가 나면 traceback 이 예외 메시지를 그대로 찍는데, 그 안에 키가 섞일 수 있었다 → 출력 전에 키를 `***` 로 바꿨다.
2. **숨겨야 할 카드가 보이던 문제**: JS 가 `hidden` 을 붙여도 CSS 의 `display: flex` 가 이겼다 → `[hidden]` 규칙을 `!important` 로 추가했다.
3. **첫 클릭이 무시되던 문제**: 버튼을 누르는 순간 오류 문구가 사라져 버튼이 위로 움직였고, 손을 뗄 때는 버튼 밖이었다 → 오류 문구를 타이핑 중에 지우도록 바꿨다.

- **원인 찾는 순서**: 화면 오류 코드 → 개발자 도구 Network 탭 → `/api/health` → Vercel Logs → 로컬에서 `--mock-error` 로 재현

## 7. 예상 질문 15개 (짧은 답)

| 번호 | 질문 | 답 |
|---|---|---|
| 1 | 이 서비스는 누구를 위한 건가요? | AI 전환을 시작하려는 중소·중견 제조기업 실무자. 3분 입력으로 보고용 로드맵·KPI 초안을 얻습니다. |
| 2 | AI 기능의 입력과 출력은? | 입력: 업종, 규모, 5개 영역 점수, 고민. 출력: 요약, 강점·보완점, 3단계 로드맵, KPI 3개, 이번 주 할 일, 주의점 |
| 3 | 단계는 AI 가 정하나요? | 아니요. 점수 합계로 코드가 계산합니다. 같은 입력이면 항상 같은 단계가 나오게 하려고요. |
| 4 | 실패 처리는 몇 가지인가요? | 빈 입력, 4xx(400·404·429), 5xx(500·502·504), 네트워크 끊김, 지연(10초 안내), 타임아웃(50초 중단) |
| 5 | 서버에서도 입력을 검사하는 이유는? | 브라우저 검사는 개발자 도구나 직접 요청으로 우회할 수 있어서요. |
| 6 | 타임아웃이 40초, 50초, 60초로 다른 이유는? | 서버가 40초에 정리된 504 안내를 먼저 보내고, 그래도 안 오면 브라우저가 50초에 멈추고, Vercel 함수는 60초에 끝나도록 순서를 맞췄습니다. |
| 7 | AI 응답이 JSON 이 아니면? | `extract_json` 이 코드블록·설명을 걷어내고, 그래도 안 되면 `AI_BAD_OUTPUT` 으로 안내합니다. |
| 8 | 프롬프트 주입은 어떻게 막나요? | 고민 문장을 따옴표 블록에 넣고 "지시가 아닌 자료"라고 명시, 시스템 프롬프트에 규칙 변경 금지를 넣었습니다. |
| 9 | 왜 Gemini 인가요? | 무료 등급이 있어 동료도 재현하기 쉽고, 환경 변수만 바꾸면 Claude·OpenAI 로 바꿀 수 있게 만들었습니다. |
| 10 | 비용·쿼터는 어떻게 관리하나요? | 요청 중 버튼 잠금, 응답 뒤 3초 제한, 서버에서 같은 IP 1분 6회 제한, 입력 500자 제한, 저렴한 경량 모델 기본값 |
| 11 | 개인정보는요? | 저장하지 않습니다. 로그에도 사용자 문장과 키를 남기지 않습니다. |
| 12 | `/api/health` 는 왜 만들었나요? | 배포 후 키·모델 설정이 맞는지(`config_ok`)를 키 노출 없이 확인하려고요. 진단 함수와 같은 규칙으로 판단하는지 테스트로 확인했습니다. |
| 13 | 커밋 이력에 fix 가 있는 이유는? | 테스트로 찾은 실제 결함 3건을 따로 고친 기록입니다. |
| 14 | 로컬 서버는 Vercel 과 어떻게 같게 만들었나요? | `/api/이름` 요청을 `api/이름.py` 의 handler 에 넘기고, `vercel.json` 헤더를 똑같이 붙입니다. |
| 15 | 다음에 개선한다면? | 결과 만족도 버튼으로 프롬프트 개선 효과 측정, 재진단 비교 화면 |

## 8. 2분 시연 순서 (평가자 앞에서)

1. 배포 URL 접속 → 상단 메뉴로 섹션 이동 (메뉴 강조 보여 주기)
2. 휴대폰 화면(개발자 도구 390px) 전환 → 햄버거 메뉴
3. 빈 상태로 제출 → "필수값을 입력하세요" 와 칸별 안내
4. "예시로 채우기" → 제출 → 로딩 문구 변화 → 결과 (단계, 레이더, 로드맵, KPI, 엔진 표시)
5. 개발자 도구 Network 탭에서 `/api/diagnose` 요청·응답 JSON 보여 주기 (키가 없다는 점 강조)
6. `/api/health` 열어 `config_ok: true` 확인
7. (시간 남으면) 로컬에서 `python scripts/dev_server.py --mock-error 429` 로 오류 안내 재현
